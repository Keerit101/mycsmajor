# Decisions

Choices made while building the site without asking, and the reasoning behind each.

## Structure

- **Multi-page app, one HTML file per page.** Every page is real HTML at a clean URL (`/daily/`, `/python-book/loops/`), so search engines can read it without running JavaScript, and each page gets its own title and description.
- **Shared layout through a small Vite plugin** (`vite.config.js`) instead of a template engine. It injects `src/partials/head.html`, `header.html` and `footer.html`, marks the current menu item, and fills in the canonical URL and Open Graph tags from each page's title and description. No extra dependencies.
- **`sitemap.xml` is generated at build time** from the list of pages, so it can never miss a page. Pages marked `noindex` (only the 404) are left out.
- **`vercel.json` sets `trailingSlash: true`** so `/daily` redirects to `/daily/`, matching the canonical URLs.

## Daily problems

- **90 problems in three tracks of 30** (Python, Logic, Data structures), stored in `src/data/tracks/*.js`, each ordered from easiest to hardest (Python 13 easy, 11 medium, 6 hard; Logic 12/12/6; Data structures 12/13/5). The 36 original problems were kept and slotted in by difficulty; 54 are new.
- **Schedule**: days rotate Python, Logic, Data structures, and each track steps one problem harder every third day, so difficulty climbs across a 90-day cycle and then repeats. The schedule starts on **23 October 2026** (`EPOCH` in `src/data/problems.js`), so launch week begins with the easiest problems. Reordering was safe because the site had not launched; from now on, only append to the end of a track.
- **Every solution is tested.** `npm test` exports all problems and runs `tests/check_solutions.py`, which executes all 60 Python solutions against their examples and edge cases, re-runs the "what does this print?" examples to confirm the claimed output, and computes every logic answer that can be computed (bridge crossing by exhaustive search, two eggs by dynamic programming, Josephus by simulation, birthday odds, water jugs by BFS and so on). It fails if any problem with code has no check.
- **Rotation by local calendar date.** Days since the epoch in the visitor's time zone, modulo 90. Everyone in the same time zone sees the same problem, and it changes at their midnight. Dates before the epoch are not shown in the archive.
- **The problem is chosen in JavaScript**, because a static build cannot know the visitor's date. Pages show a `<noscript>` message without JS. Everything else on the site works without JS.
- **Hidden solutions use `<details>`**, so they are accessible to keyboard and screen-reader users. They are hidden, not secret: a determined visitor can read them in the page source, which is fine for practice problems.
- **Streak rules**: pressing "I solved it" on consecutive days adds to the streak; missing a day resets it to 0. Stored in `localStorage` under `mycsmajor:streak:v1` with current streak, best streak, total and up to 400 solved dates. One-level **undo** is included for accidental clicks. Corrupt or blocked storage falls back safely.
- **Only today's problem counts** towards the streak. The archive lists the past 14 days (since launch) as links to each problem's own page and marks which ones you solved.

## Problem pages and sharing

- **Every problem has its own page** at `/problems/<slug>/`, plus an index at `/problems/` listing all 90 by track. The pages are **generated** by `scripts/generate-problem-pages.mjs` from the problem data before every `npm run dev` and `npm run build`, so they can never drift out of sync with the data. The generated `problems/` folder is git-ignored. Vercel runs `npm run build`, so it generates them too.
- **Problem page titles and descriptions are built from the data**: the title is "<Problem>: <Track> Practice Problem | mycsmajor", shortened when it would pass 65 characters, and the description is the difficulty and track plus the start of the prompt, ending "Hint and full solution included." `scripts/check-seo.mjs` (`npm run check:seo`) checks every built page for unique titles and descriptions, sensible lengths, one `<h1>`, canonical and social tags, and sitemap coverage.
- **Problem pages show the hint and solution hidden in `<details>`**, like the daily page, plus links to the next easier and harder problem in the same track. The "I solved it" streak button stays on the Daily Problem page only, to keep problem pages fast and fully static.
- **Main menu**: "Problems" was added and "Contact" moved to the footer only, to keep the menu to six items.
- **One site-wide share image** (`public/og.png`, 1200 by 630) is generated by `npm run share-image`, which renders an HTML card in the site's font and colours with headless Edge or Chrome. It is committed because Vercel's build has no browser. Per-problem images were skipped: they would add about 3 MB of PNGs to the repo and need regenerating locally for every new problem. Every page has Open Graph and Twitter Card tags (`summary_large_image`) with this image; problem pages and book chapters use `og:type` "article".

## Money

- **Affiliate disclosure page** at `/affiliate-disclosure/`, linked from the footer on every page, from the disclosure box on Gear Guides and from the privacy policy. It explains affiliate links and future ads in plain language and is honest that the buy links do not earn anything yet. I left out any promise about free products, which is your call.
- **The nine gear links keep their `data-affiliate="TODO"` markers** and still point to the makers' sites.
- **Ad slots are empty `<aside>` elements with the `hidden` attribute**, each preceded by an `<!-- AD SLOT: name -->` comment and labelled "Advertisement" for screen readers. Placements: below today's problem on Home, after each problem and book chapter, on the problem index, and halfway down Cyber Brief. None on Gear Guides (ads would compete with the affiliate links) or on the Daily Problem page (keeps the habit page clean). When shown, a slot reserves 280px of height so the page does not jump while an ad loads.
- **`src/js/ads.js` holds the AdSense switch.** With no publisher ID (the default) it returns immediately and loads nothing, so there is no performance or privacy cost today. Turning it on is a two-constant change, but the privacy policy and a consent banner must come first (see TODO.md).

## Content

- **Cyber Brief covers 12 real, documented incidents**, newest first (Log4Shell, xz, Heartbleed, Citrix Bleed, Ivanti Connect Secure, Baron Samedit, Spectre and others) with links to their official NVD records, instead of "latest news". Without a news API or an editor, a news feed would be invented or quickly stale. Each brief ends with a coding lesson for students. See TODO.md about adding current news.
- **Gear Guides name product lines, not exact models or prices** (for example "Sony WH-1000X series"), because models and prices change often. Buy buttons go to each maker's site for now. Every one is marked `data-affiliate="TODO"` with an HTML comment, so `grep -rn 'data-affiliate="TODO"'` finds them all. They use `rel="nofollow noopener"`; add `sponsored` when you switch to real affiliate URLs. An affiliate disclosure is on the page and in the footer.
- **Python Book has twelve chapters** in two parts, each at its own URL with three exercises and hidden answers. Every output shown in the chapters was checked by running it. The brief for round 2 asked for chapters on functions, files, dictionaries, classes, errors and testing; functions and dictionaries already had beginner chapters (5 and 6), so the new chapters 7 and 8 go further ("More functions", "Dictionaries and sets") rather than repeat them.
- **The About page describes the site, not a person.** I did not invent a founder bio. Add one if you want (see TODO.md).
- **Contact uses a mailto form** because the site has no backend. It needs no third-party service and sends no data anywhere until the visitor presses send in their own email app. The address `hello@mycsmajor.com` is a placeholder until you set up that mailbox.
- **No emoji anywhere**, per the brief.

## Design

- **One text font: Inter** (variable), self-hosted through `@fontsource-variable/inter`, so no request goes to Google Fonts. That is better for privacy and means there are no third parties to disclose.
- **Code uses a monospace font** (changed in round 2 at the owner's request). It is a system font stack (`--mono` in `src/styles.css`: ui-monospace, Cascadia Mono, Consolas, SF Mono, Menlo), so it adds no download. Ligatures are off. Comments in code samples are aligned in columns again.
- **Colours**: off-white `#faf9f6` background, near-black `#111` text, one blue accent `#1d4ed8` (6.4:1 contrast on the background, passes WCAG AA). A muted grey is used only for secondary text.
- **No shadows at all**; 1px borders separate surfaces.
- **No sideways scrolling on the page**: grids collapse to one column on phones and `overflow-x: clip` on the body is a safety net. **Code blocks keep their real indentation** (`white-space: pre`) and scroll sideways *inside the block* when a line is too long, instead of wrapping, because wrapped Python lines look like wrong indentation. A scrolling code block gets `tabindex="0"` and a label (`src/js/scrollable.js`) so keyboard users can scroll it. The check script verifies at 320px, 360px and 1366px, with all `<details>` opened, that the page never scrolls sideways (content inside a `<pre>` is allowed to).
- **Mobile menu**: on narrow screens the nav collapses behind a Menu button. A tiny inline script adds a `js` class before first paint, so the menu does not flash open, and without JavaScript the full menu simply stays visible.

## Privacy and SEO

- **No analytics and no cookies.** The privacy policy says so and promises an update before that changes.
- **Analytics is ready but off.** The Vercel Web Analytics snippet (cookieless, chosen because the site already runs on Vercel and needs no consent banner for cookies) sits commented out in `src/partials/head.html`. It uses a placeholder `UNIQUE-PATH`, because Vercel now gives each project its own script path in the dashboard (checked against Vercel's docs on 23 October 2026), and a guessed path would 404. Turning it on means updating the privacy policy too, so it is left for you (TODO.md).
- **The privacy page is indexable** and listed in the sitemap. Only the 404 page is `noindex`.
- **Titles are at most about 65 characters and descriptions 105 to 170 characters**, each unique per page (checked with a script during the build).

## Tooling

- **Vite 8** (latest at build time) with no other build dependencies. `playwright-core` is a dev dependency for the check script; it drives the Edge or Chrome already installed rather than downloading a browser.
- **Git**: its own repository in this folder, LF line endings via `.gitattributes`, one commit per finished page.

## Quality (round 2)

- **Lighthouse (mobile settings, run locally against `npm run preview` on 23 October 2026)**: Home, Daily, a problem page, two book chapters, About and the affiliate disclosure all scored **100** for performance, accessibility, best practices and SEO, as did Gear, Cyber Brief and the problem index in the first run. Real-world scores on Vercel will differ a little with network conditions.
- **Two fixes came out of it.** Home and Daily scored 77 and 81 on performance, because today's problem is inserted by JavaScript and pushed the content below it down (layout shift 0.59). The content below the problem and the footer now stay invisible until the problem is in place (`has-today` / `today-ready` classes), with a CSS fallback that reveals them after 3 seconds if the script fails. The headline still paints immediately. Book chapters shifted when the Inter font arrived, so the Latin subset of Inter is now preloaded on every page by a small build plugin (`preloadFont` in `vite.config.js`). Layout shift is now 0 on all audited pages.
- **Accessibility is checked on every page, not just a sample.** `npm run check` now also runs axe-core's WCAG 2.1 A and AA rules on all 113 pages at 320, 360 and 1366px, with every hint and solution opened. All pass.
- **Keyboard focus**: every focusable element type (skip link, menu, links, cards, buttons, `<summary>`, form fields and scrollable code blocks) shows a 2px blue focus ring, checked by tabbing through the pages.
- **Contrast** (WCAG AA needs 4.5:1 for body text): text #111 on the background is about 18:1, the muted grey 8.4:1, the blue accent 6.4:1 on the background and 5.8:1 on the pale blue, and white on blue buttons 6.7:1.
- **Alt text**: the site has no `<img>` elements; the only images are the favicon and the social share image, which has `og:image:alt` and `twitter:image:alt` text.
