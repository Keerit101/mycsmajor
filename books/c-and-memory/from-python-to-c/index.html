C and how memory really works · Chapter 1

From Python to C

C gives you almost nothing and checks almost nothing. That is why learning it teaches you what a computer is actually doing with your program.

Get a compiler

  • Linux: sudo apt install build-essential (or your distribution's equivalent) gives you gcc.
  • macOS: run xcode-select --install to get clang, which answers to gcc too.
  • Windows: install the Windows Subsystem for Linux and work inside it, or install MSYS2 and use its gcc. Working in a Unix-like shell is worth it: almost all C teaching material assumes one.
gcc --version

Hello, C

Put this in hello.c:

#include <stdio.h>

int main(void) {
    printf("Hello, world!\n");
    return 0;
}

Compile it and run it:

gcc -Wall -Wextra -o hello hello.c
./hello
Hello, world!

Line by line:

  • #include <stdio.h> pastes in the declarations for the standard input and output functions, printf among them. It is not an import; it is a literal copy and paste done by the preprocessor before compiling.
  • int main(void) is where the program starts. It returns an int to the operating system: 0 means success, anything else means failure. void means it takes no arguments.
  • printf prints. There is no automatic newline, so you write \n yourself.

Always compile with -Wall -Wextra. C will happily compile code that is broken; those two flags make the compiler tell you about the obvious cases. Treat every warning as an error you have not hit yet.

printf is not print

Python's print works out how to display anything. printf does not: you tell it, with a placeholder for each value, and it trusts you.

int marks = 90;
double average = 84.6666;
char grade = 'A';
char name[] = "Keerit";

printf("%d\n", marks);           // 90
printf("%.2f\n", average);       // 84.67
printf("%c\n", grade);           // A
printf("%s\n", name);            // Keerit
printf("%d%%\n", marks);         // 90%   (%% prints one percent sign)

The common ones are %d for int, %f for double (%.2f for two decimals), %c for a character, %s for a string and %zu for a size. Use the wrong one and C does not complain at run time; it reinterprets the bytes and prints nonsense. This is your first lesson in what "no safety net" means.

Types are not optional

int count = 3;          /* whole number, 4 bytes on almost every machine */
double ratio = 0.75;    /* decimal, 8 bytes */
char letter = 'x';      /* one byte */
int marks[5];           /* room for five ints, contents undefined */

Three differences from Python will catch you:

  1. A variable has a fixed size. sizeof(int) is 4 bytes on a normal desktop, so an int stops at about 2.1 billion and then wraps around silently.
  2. A declared variable is not empty, it is undefined. int x; contains whatever bytes were already at that address. Reading it before assigning is undefined behaviour, and the value may differ every run. Always initialise: int x = 0;
  3. Integer division truncates, as in Java: 7 / 2 is 3, and 7 / 2.0 is 3.50.

There are no real strings

A C string is an array of characters with a zero byte on the end, written '\0'. The functions in <string.h> find the end by looking for that byte.

#include <stdio.h>
#include <string.h>

int main(void) {
    char word[] = "hi";
    printf("%zu %zu\n", sizeof(word), strlen(word));   /* 3 2 */
    return 0;
}

sizeof is 3 because the array holds 'h', 'i' and '\0'. strlen is 2 because it counts up to, but not including, the terminator. If that zero byte goes missing, strlen keeps reading past the end of your array into memory that is not yours. That single design decision is behind a remarkable number of real security vulnerabilities.

You cannot join strings with +, compare them with ==, or ask one how long it is. You call functions: strlen, strcmp, strcpy, snprintf. Chapter 3 covers them, including which ones are dangerous.

Arrays do not know their own length

int nums[5] = {1, 2, 3, 4, 5};
printf("%d\n", nums[2]);     /* 3 */
printf("%d\n", nums[7]);     /* no error: reads whatever is 7 ints along */

There is no len() and no bounds check. nums[7] compiles, runs, and prints whatever happened to be in that memory. Sometimes it crashes; more often it quietly returns rubbish, or overwrites a variable you care about. You carry the length yourself:

int nums[5] = {1, 2, 3, 4, 5};
int n = 5;                                   /* pass n everywhere you pass nums */
for (int i = 0; i < n; i++) {
    printf("%d ", nums[i]);
}
printf("\n");                                /* 1 2 3 4 5 */

Inside the function that declares the array you can compute the length with sizeof(nums) / sizeof(nums[0]), but once the array is passed to another function that trick silently stops working, for a reason that chapter 3 makes clear.

The whole build in one line

What gcc -o hello hello.c actually does, in order:

  1. Preprocess: paste in every #include, expand every #define.
  2. Compile: turn the result into assembly for your processor.
  3. Assemble: turn assembly into an object file of machine code.
  4. Link: join your object file to the standard library (that is where printf really lives) and produce one executable.

You can see the stages with gcc -E hello.c (preprocessed source, usually hundreds of lines) and gcc -c hello.c (object file only). Knowing these four steps turns "undefined reference to printf" from a mystery into a linking problem.

Exercises

1. Sizes on your machine

Print the size in bytes of char, int, long, double and a pointer.

Show answer 
#include <stdio.h>

int main(void) {
    printf("char   %zu\n", sizeof(char));
    printf("int    %zu\n", sizeof(int));
    printf("long   %zu\n", sizeof(long));
    printf("double %zu\n", sizeof(double));
    printf("int *  %zu\n", sizeof(int *));
    return 0;
}

On a 64-bit Linux or macOS machine this prints 1, 4, 8, 8 and 8. char is 1 byte by definition; the rest depend on the platform, which is why portable code uses the fixed-width types in <stdint.h> such as int32_t.

2. The average, again

Store three marks in an array, then print their average to two decimal places.

Show answer 
#include <stdio.h>

int main(void) {
    int marks[3] = {90, 80, 84};
    int total = 0;
    for (int i = 0; i < 3; i++) {
        total += marks[i];
    }
    printf("Average: %.2f\n", total / 3.0);   /* Average: 84.67 */
    return 0;
}

Divide by 3.0, not 3. With 3 the division happens in integers, giving 84, and %.2f would then be given an int where it expects a double — undefined behaviour, and usually a nonsense number.

3. Walk off the end

Declare int nums[3] = {1, 2, 3}; and print nums[5] and nums[50]. Run it several times. Then compile with gcc -fsanitize=address and run it again.

Show answer

Without the sanitiser you usually get a number that means nothing, and it may change between runs or between machines. nums[50] is more likely to crash with a segmentation fault, because it reaches further outside the memory your program was given.

With -fsanitize=address the program stops and prints a report naming the file, the line and how far past the end of the array you read. Use that flag while you are learning: it turns silent corruption into a clear error, which is exactly what C otherwise refuses to do for you.
