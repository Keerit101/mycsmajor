C and how memory really works · Chapter 2

Pointers without fear

A pointer is a variable that holds an address. That is the whole idea. Everything confusing about pointers is notation, so this chapter goes slowly through the notation.

Memory is a very long street

Think of memory as a street of numbered boxes, one byte each. A variable is a label your program puts on a box, or on several boxes in a row. The number of the first box is the variable's address.

Two operators do everything:

  • &x gives the address of x. Read it as "address of".
  • *p gives the value stored at the address in p. Read it as "the thing at".
#include <stdio.h>

int main(void) {
    int x = 42;
    int *p = &x;        /* p holds the address of x */

    printf("%d\n", x);   /* 42 */
    printf("%d\n", *p);  /* 42, the thing at that address */

    *p = 7;              /* write through the pointer */
    printf("%d\n", x);   /* 7, because p pointed at x */
    return 0;
}

Drawn out, after int *p = &x;:

    address      contents     label
    0x7ffd1004 | 42        | x
    0x7ffd1008 | 0x7ffd1004| p     (p's contents are x's address)

The actual addresses differ on every run; only the relationship matters. *p = 7 does not change p at all. It changes the box p is pointing at.

The star means two different things

This is the single biggest source of confusion, and it is worth being blunt about.

int *p;      /* DECLARATION: p is a pointer to an int */
*p = 7;      /* STATEMENT:   write 7 into the int that p points at */

In a declaration, * is part of the type. In an expression, * is the dereference operator. The compiler always knows which is which from context; you have to as well. A habit that helps: read declarations from the variable outwards. int *p is "*p is an int", so p must be a pointer to an int.

Print an address with %p:

printf("%p\n", (void *) &x);   /* e.g. 0x7ffd1004 */

Why pointers exist: changing a caller's variable

C passes every argument by value: the function gets a copy. So this classic swap does nothing at all.

void bad_swap(int a, int b) {
    int t = a;
    a = b;
    b = t;              /* swaps the copies, then they are thrown away */
}

int x = 1, y = 2;
bad_swap(x, y);
printf("%d %d\n", x, y);   /* 1 2 */

Pass the addresses instead, and the function can reach the originals:

void good_swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

good_swap(&x, &y);
printf("%d %d\n", x, y);   /* 2 1 */

This is why scanf takes an &: scanf("%d", &n) hands it the address of n so it can fill it in. Forgetting the & passes whatever rubbish is in n as an address and corrupts memory there. Compilers warn about it, which is one more reason for -Wall.

Python does not need any of this because every Python variable is already a reference to an object. C makes the choice explicit on every parameter.

Arrays are nearly pointers

int nums[5] = {1, 2, 3, 4, 5};
printf("%d\n", nums[2]);        /* 3 */
printf("%d\n", *(nums + 2));    /* 3, the same thing */

In almost every expression, an array's name becomes a pointer to its first element. So nums[2] is defined as *(nums + 2): start at the beginning and move two elements along. Note elements, not bytes: adding 1 to an int * moves 4 bytes, because the compiler knows what it points at. That is pointer arithmetic, and it is why the type of a pointer matters.

This decay is also why an array forgets its length when you pass it:

void print_all(int values[], int n) {   /* values is really an int *   */
    for (int i = 0; i < n; i++) {       /* so n has to come along too   */
        printf("%d ", values[i]);
    }
    printf("\n");
}

Inside print_all, sizeof(values) is the size of a pointer, not of the array. Every C function that takes an array takes a length beside it. When you see that pattern in the standard library, now you know why.

Pointers to pointers, and const

char *name = "Keerit";        /* pointer to the first character       */
char **list;                  /* pointer to a pointer: an array of     */
                              /* strings is usually written this way    */

const char *msg = "cannot change this text through msg";

const is a promise to the compiler, and it is checked. Mark a pointer parameter const whenever the function only reads through it, and the compiler will stop you writing through it by accident. String literals in particular live in read-only memory: writing to one is undefined behaviour and usually crashes, so always point at them with a const char *.

NULL, and the three ways pointers go wrong

NULL is the address zero, used to mean "points at nothing". Dereferencing it is a segmentation fault, which, as crashes go, is the good outcome: it stops immediately instead of corrupting something.

The three classic failures, each covered in full later in the book:

  1. Uninitialised pointer. int *p; then *p = 5; writes to a random address. Always initialise: int *p = NULL;
  2. Dangling pointer. The thing it pointed at is gone, because a function returned or the memory was freed. Chapters 4 and 5.
  3. Out of bounds. Pointer arithmetic that walks past the end of an array. No check happens.

Two habits prevent most of this: initialise every pointer, and test with gcc -fsanitize=address,undefined while you are learning.

Exercises

1. Predict the output

int a = 5;
int b = 10;
int *p = &a;
int *q = &b;
*p = *q;
p = q;
*p = 20;
printf("%d %d\n", a, b);
Show answer

10 20.

*p = *q copies the value, so a becomes 10. p = q copies the pointer, so p now points at b. *p = 20 therefore writes into b, leaving a at 10.

If you got this right, you understand pointers. The rest of the book is detail.

2. Two results from one function

Write void min_max(const int values[], int n, int *min, int *max) that fills in both answers through its pointer parameters.

Show answer 
void min_max(const int values[], int n, int *min, int *max) {
    *min = values[0];
    *max = values[0];
    for (int i = 1; i < n; i++) {
        if (values[i] < *min) *min = values[i];
        if (values[i] > *max) *max = values[i];
    }
}

/* called like this: */
int lo, hi;
int data[5] = {4, 9, 1, 7, 3};
min_max(data, 5, &lo, &hi);
printf("%d %d\n", lo, hi);   /* 1 9 */

A C function returns one value, so when you need two, you pass pointers to where the answers should go. This pattern is everywhere in C libraries. Starting at values[0] rather than at zero matters: with all-negative input, a maximum initialised to 0 would be wrong.

3. Write your own strlen

Write size_t my_strlen(const char *s) using pointer arithmetic, without using strlen.

Show answer 
size_t my_strlen(const char *s) {
    const char *start = s;
    while (*s != '\0') {
        s++;
    }
    return (size_t)(s - start);
}

Walk forward until the terminating zero byte, then subtract the starting address from the final one: the difference between two pointers into the same array is the number of elements between them. This is, give or take some optimisation, exactly what the real strlen does — and it shows why a string with no terminator makes it run off the end of memory.
