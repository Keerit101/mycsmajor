Arrays, lists and when each wins

A Python list looks like one thing that does everything. Underneath it is a specific data structure with specific costs, and knowing them explains most "why is my code slow" questions.

An array is a row of boxes

An array is a block of memory holding equal-sized slots, one after another. Because the slots are equal and adjacent, the computer can find slot i by arithmetic:

address of xs[i]  =  address of xs[0]  +  i × size of one slot

One multiplication and one addition, whatever i is. That is why xs[0] and xs[999_999] cost the same: O(1). Everything else about arrays follows from this one fact.

It also explains why C arrays need a fixed element type: if the slots were different sizes, the arithmetic would not work and the computer would have to walk the array to find anything.

What a Python list really is

A Python list is a dynamic array: an array with spare room on the end, plus a stored length. When the spare room runs out, Python allocates a bigger block, copies everything over, and frees the old one.

xs = [10, 20, 30]        # length 3, capacity maybe 4

    index:     0    1    2    3
    slots:  [ 10 | 20 | 30 |    ]
                              spare

So append is usually one write into the spare slot, and occasionally a full copy. Averaged out, it is O(1) amortised. The growth is by a factor, not by a fixed amount, which is what keeps the average constant: doubling means the expensive copies get rarer exactly as fast as they get bigger.

Three of these cause almost all real slowness: pop(0), insert(0, v) and in.

Why the front is expensive

Inserting at index 0 means every existing item must move up one slot to make room, because the index of an item is its position in the block.

before:  [ 10 | 20 | 30 |    ]
insert 5 at 0
after:   [  5 | 10 | 20 | 30 ]
              every item shifted right

Measured over 100,000 operations on an empty list, on the machine these pages were written on:

import timeit
print(timeit.timeit("xs.append(1)",    setup="xs=[]", number=100_000))   # about 0.002 s
print(timeit.timeit("xs.insert(0,1)",  setup="xs=[]", number=100_000))   # about 0.9 s

Several hundred times slower, and the gap widens as the list grows, because each insert shifts a longer list. Building a list by inserting at the front is O(n²) overall.

Two fixes. If you want newest-first, append and then reverse() once at the end, which is O(n) in total. If you genuinely need to add and remove at both ends, use a deque:

from collections import deque

q = deque([10, 20, 30])
q.appendleft(5)      # O(1)
q.popleft()          # O(1)

A deque is a doubly linked list of small blocks, so both ends are cheap — but q[i] in the middle becomes O(n). You never get everything; you choose what to pay for.

The most common upgrade a beginner can make is replacing if x in some_list with a set built once, outside the loop. It usually takes two lines and turns quadratic code linear.

Two-dimensional lists, and the trap

grid = [[0] * 3 for _ in range(3)]   # three separate rows: correct
bad  = [[0] * 3] * 3                 # three references to ONE row

bad[0][0] = 9
print(bad)    # [[9, 0, 0], [9, 0, 0], [9, 0, 0]]

* 3 on a list copies references, not the rows. The comprehension builds a new inner list each time round, which is what you almost always want. This one catches nearly everybody once.

Exercises

1. Name the cost

Give the total time complexity of each loop, in terms of n = len(data).

# (a)
out = []
for x in data:
    out.insert(0, x)

# (b)
out = []
for x in data:
    out.append(x)
out.reverse()

# (c)
result = []
for x in data:
    if x not in result:
        result.append(x)
Show answer

(a) O(n²). Each insert(0, x) shifts everything already there, so the total is 0 + 1 + 2 + ... + (n−1) shifts.

(b) O(n). Each append is amortised O(1), and one reverse is O(n). Same result as (a), hundreds of times faster.

(c) O(n²). x not in result scans the list each time. To deduplicate while keeping order, use dict.fromkeys(data), which is O(n) and preserves insertion order.

2. Build a dynamic array yourself

Using a fixed-size array as the only storage, write a class with append and get that grows by doubling. Use [None] * capacity as your "fixed array" and never resize it in place.

Show answer 
class DynamicArray:
    def __init__(self):
        self._capacity = 1
        self._size = 0
        self._slots = [None] * self._capacity

    def __len__(self):
        return self._size

    def get(self, i):
        if not 0 <= i < self._size:
            raise IndexError(i)
        return self._slots[i]

    def append(self, value):
        if self._size == self._capacity:
            self._grow()
        self._slots[self._size] = value
        self._size += 1

    def _grow(self):
        self._capacity *= 2
        bigger = [None] * self._capacity
        for i in range(self._size):      # the expensive copy
            bigger[i] = self._slots[i]
        self._slots = bigger

Add a print inside _grow and append 100 items: it fires at sizes 1, 2, 4, 8, 16, 32 and 64, seven times for a hundred appends. That is why the average stays constant. Change *= 2 to += 1 and it fires every single time, making append O(n) and the whole loop O(n²).

3. Pick the structure

For each job, name the structure and the cost: (a) the last 50 pages a user visited, newest first; (b) checking whether a username is taken, from 2 million names; (c) counting how many times each word appears in an essay.

Show answer

(a) deque(maxlen=50) with appendleft: O(1) per page, and it drops the oldest automatically.

(b) a set of names: O(1) per check. In a list this is O(n), which at two million names is the difference between instant and noticeable on every sign-up.

(c) collections.Counter(words), a dict underneath: O(n) in total, O(1) per word. Writing counts[w] = counts.get(w, 0) + 1 by hand is the same cost and worth doing once to see why.
