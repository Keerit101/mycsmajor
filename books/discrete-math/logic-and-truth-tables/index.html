Discrete math and logic · Chapter 1

Logic and truth tables

Everything in a discrete maths course is built on this chapter, and so is every if statement you will ever write. It is worth being properly comfortable here.

Statements

A statement (or proposition) is a sentence that is either true or false, not both. "7 is prime" is a statement. "Close the door" and "x > 3" are not: the first is a command, the second depends on x, which makes it a predicate, the subject of chapter 3.

Letters stand for statements: p, q, r. From them you build compound statements with connectives.

NameSymbolEnglishIn code
negation¬pnot pnot p
conjunctionp ∧ qp and qp and q
disjunctionp ∨ qp or qp or q
implicationp → qif p then q(not p) or q
biconditionalp ↔ qp if and only if qp == q
exclusive orp ⊕ qp or q but not bothp != q

One warning about English: "or" in logic is inclusive. "Tea or coffee" in a café means one of them; p ∨ q in maths is true when both are true.

Truth tables

A truth table lists every combination of truth values. With n letters there are 2n rows, so two letters give four rows and three give eight.

p   q  | p∧q | p∨q | p→q | p↔q | p⊕q
-------+-----+-----+-----+-----+-----
T   T  |  T  |  T  |  T  |  T  |  F
T   F  |  F  |  T  |  F  |  F  |  T
F   T  |  F  |  T  |  T  |  F  |  T
F   F  |  F  |  F  |  T  |  T  |  F

Write the rows in that order every time (TT, TF, FT, FF). Markers scan for the pattern, and a consistent order makes your own mistakes easier to spot.

The row everybody argues about

Look at p → q when p is false: the implication is true, both times. This feels wrong until you read an implication as a promise.

"If it rains, I will bring an umbrella." You only broke that promise in one situation: it rained and you did not bring one. If it did not rain, you kept the promise whatever you carried. An implication is false in exactly one row, p true and q false, and true everywhere else. A promise about a situation that never happened is said to be vacuously true.

This also gives you the most useful identity in the chapter:

p → q  ≡  ¬p ∨ q

Check it against the table above, row by row. Any time an implication is hard to work with, rewrite it this way.

Building a table for something bigger

Show that ¬(p ∧ q) ≡ ¬p ∨ ¬q, one of De Morgan's laws. Add a column per piece:

p   q  | p∧q | ¬(p∧q) | ¬p | ¬q | ¬p∨¬q
-------+-----+--------+----+----+-------
T   T  |  T  |   F    | F  | F  |   F
T   F  |  F  |   T    | F  | T  |   T
F   T  |  F  |   T    | T  | F  |   T
F   F  |  F  |   T    | T  | T  |   T

The fourth and seventh columns match in every row, so the two statements are logically equivalent, written with ≡. That is what a truth-table proof is: identical columns.

Three words for the shape of the final column: a tautology is true in every row, a contradiction is false in every row, and a contingency is sometimes each.

The laws worth knowing by name

Every one of these can be proved with a truth table, and your course will expect you to use them to simplify expressions without one.

LawForm
Identityp ∧ T ≡ p,   p ∨ F ≡ p
Dominationp ∨ T ≡ T,   p ∧ F ≡ F
Idempotentp ∧ p ≡ p,   p ∨ p ≡ p
Double negation¬(¬p) ≡ p
Complementp ∨ ¬p ≡ T,   p ∧ ¬p ≡ F
Commutativep ∧ q ≡ q ∧ p
Associative(p ∧ q) ∧ r ≡ p ∧ (q ∧ r)
Distributivep ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r)
De Morgan¬(p ∧ q) ≡ ¬p ∨ ¬q,   ¬(p ∨ q) ≡ ¬p ∧ ¬q
Absorptionp ∨ (p ∧ q) ≡ p
Contrapositivep → q ≡ ¬q → ¬p

De Morgan's laws are the ones you will use most, in maths and in code. "Not (logged in and verified)" is the same as "not logged in or not verified": negation flips the connective.

A simplification, step by step

Simplify ¬(p ∨ (¬p ∧ q)). Name the law at each step, because that is what the marks are for.

¬(p ∨ (¬p ∧ q))
≡ ¬p ∧ ¬(¬p ∧ q)        De Morgan
≡ ¬p ∧ (p ∨ ¬q)           De Morgan, then double negation
≡ (¬p ∧ p) ∨ (¬p ∧ ¬q)  Distributive
≡ F ∨ (¬p ∧ ¬q)            Complement
≡ ¬p ∧ ¬q                   Identity

Check the answer with a truth table if you have time in an exam. It is four rows and it catches a dropped negation immediately.

The same logic, in your code

Simplifying conditions is the same operation:

if not (age >= 18 and has_id):          # hard to read
if age < 18 or not has_id:             # De Morgan, same meaning

One real difference: Python and Java short-circuit. In p and q, q is only evaluated if p is true, which is why if user is not None and user.name == "x" is safe. Truth tables say nothing about evaluation order, so simplifying a condition can change which side runs. Keep the null check on the left.

Exercises

1. Build the table

Show with a truth table whether (p → q) ∧ (q → p) is equivalent to p ↔ q.

Show answer 
p   q  | p→q | q→p | (p→q)∧(q→p) | p↔q
-------+-----+-----+---------------+-----
T   T  |  T  |  T  |       T       |  T
T   F  |  F  |  T  |       F       |  F
F   T  |  T  |  F  |       F       |  F
F   F  |  T  |  T  |       T       |  T

The last two columns match, so yes, they are equivalent. This is why "if and only if" is proved in two directions: you show p → q and then q → p, and together they give the biconditional.

2. Converse, inverse, contrapositive

For "if a number is divisible by 4, then it is even", write the converse, the inverse and the contrapositive, and say which are true.

Show answer

Original, p → q: if divisible by 4, then even. True.

Converse, q → p: if even, then divisible by 4. False — 6 is even and not divisible by 4.

Inverse, ¬p → ¬q: if not divisible by 4, then not even. False — 6 again.

Contrapositive, ¬q → ¬p: if not even, then not divisible by 4. True.

The pattern is the point: a statement and its contrapositive are always equivalent, so proving one proves the other. The converse and the inverse are equivalent to each other but not to the original. Assuming the converse is the most common logical error in first-year proofs.

3. Simplify with named laws

Simplify (p ∧ q) ∨ (p ∧ ¬q), naming the law at each step.

Show answer 
(p ∧ q) ∨ (p ∧ ¬q)
≡ p ∧ (q ∨ ¬q)      Distributive
≡ p ∧ T               Complement
≡ p                     Identity

In code this is the refactor from if (logged_in and admin) or (logged_in and not admin) down to if logged_in. Conditions in real programs grow exactly this way, and the laws are how you cut them back.
