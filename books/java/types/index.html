Java after Python · Chapter 2

Types, and why Java insists

The rules in this chapter cause most of the marks lost in a first Java course. None of them are hard; they are just unfamiliar if you learned Python first.

Two kinds of value

In Python everything is an object. In Java there are two families.

Primitives hold a value directly and are written in lower case: int, long, double, float, boolean, char, byte, short. They are fast, they cannot be null, and they have no methods.

Reference types are objects, and their names are capitalised: String, Integer, ArrayList, and every class you write. A variable of a reference type holds a reference to an object elsewhere in memory, or null.

int count = 3;              // a primitive, the value 3 itself
String name = "Keerit";     // a reference to a String object
int[] marks = new int[5];   // a reference to an array of five ints

Every variable states its type, and that type never changes. count = "three"; does not fail at run time as it would in Python. It fails to compile.

The sizes that matter

TypeHoldsRange
intwhole numbersabout −2.1 billion to 2.1 billion
longwhole numbersabout ±9.2 quintillion
doubledecimalsabout 15 significant digits
booleantrue or falsenothing else, ever
charone charactersingle quotes: 'A'

Use int for counting and double for measuring. Reach for long when a count might pass two billion, and write the literal with an L:

long big = 3_000_000_000L;   // underscores are allowed, for readability
System.out.println(big);     // 3000000000

Leave off the L and the compiler rejects the line, because the number does not fit in an int before it is assigned.

Overflow is silent

System.out.println(Integer.MAX_VALUE + 1);   // -2147483648

Python grows integers as large as your memory allows. Java does not: an int is 32 bits, and one past the top wraps around to the bottom. No exception, no warning. When a value could get large, use long.

Integer division

int a = 7, b = 2;
System.out.println(a / b);            // 3
System.out.println(a % b);            // 1
System.out.println((double) a / b);   // 3.5
System.out.println(5 / 2.0);          // 2.5

Two integers divide to an integer, with the remainder thrown away. Python spells this 7 // 2; Java reuses /, which is why so many Java averages come out wrong. If either side is a double, the result is a double.

(double) a is a cast: it tells the compiler to treat that value as another type. Casting the other way loses information, and Java makes you say so explicitly:

double price = 19.99;
int rounded = (int) price;      // 19, the decimal part is cut off, not rounded
int better = (int) Math.round(price);   // 20

And decimals are still binary approximations, exactly as in Python:

System.out.println(0.1 + 0.2);   // 0.30000000000000004

Never use double for money. Count cents in an int or a long, or use BigDecimal.

Characters are numbers

char c = 'A';
System.out.println((int) c);        // 65
System.out.println(c + 1);          // 66   (char promoted to int)
System.out.println((char)(c + 1));  // B

Use single quotes for a char and double quotes for a String. They are not interchangeable: "A" is an object, 'A' is a number.

Strings and numbers

String s = "42";
System.out.println(Integer.parseInt(s) + 1);   // 43
System.out.println(s + 1);                     // 421

The second line is the classic bug. + with a string on one side means "join", so the number becomes text. Python would have thrown a TypeError and saved you; Java prints 421 and lets you find out in the marking.

Going the other way, String.valueOf(n) or "" + n turns a number into text, and Double.parseDouble handles decimals. If the text is not a number, parseInt throws NumberFormatException, which chapter 9 shows how to handle.

Comparing: == against equals

This is the rule to memorise. For primitives, == compares values. For objects, == compares references: it asks whether the two variables point at the same object, not whether the objects look the same.

String x = "hi";
String y = "h" + "i";
String z = new String("hi");

System.out.println(x == y);        // true   (both are the same literal, joined at compile time)
System.out.println(x == z);        // false  (a different object, same text)
System.out.println(x.equals(z));   // true   (same characters)

So: compare objects with .equals(), always. The fact that x == y happened to be true above is an optimisation, not a rule you can rely on; read a line of text from the user and it will be false. Comparing strings with == is the single most common bug in first-year Java.

For a case-insensitive comparison use x.equalsIgnoreCase(z), and to sort, x.compareTo(z), which returns a negative number, zero or a positive number.

null, and the exception named after it

A reference variable that points at nothing holds null. Calling a method on it throws a NullPointerException, the most common crash in Java:

String name = null;
System.out.println(name.length());   // NullPointerException

Check first (if (name != null)), or avoid holding null at all by giving variables a real value when you declare them. Primitives cannot be null, which is one reason to prefer int over Integer unless you need an object.

Boxing

Each primitive has a matching class: int and Integer, double and Double, boolean and Boolean. Java converts between them automatically, which is called boxing:

Integer boxed = 5;                 // boxed from int
System.out.println(boxed + 5);     // 10, unboxed again

You need the class versions because collections such as ArrayList<Integer> can only hold objects. Watch out: two Integer objects must also be compared with .equals(), for the same reason strings must.

var, and when to use it

var total = 0;                        // an int
var names = new ArrayList<String>();  // an ArrayList<String>

var lets the compiler work out the type from the right-hand side. The variable is still statically typed and the type still cannot change: this is shorthand, not Python. Use it when the type is obvious from the same line, and write the type out when it is not.

Exercises

1. The average that lies

This prints 84, not 84.666.... Explain why, then fix it so it prints the real average.

int a = 90, b = 80, c = 84;
System.out.println("Average: " + (a + b + c) / 3);
Show answer

a + b + c is 254, an int, and 254 / 3 is integer division, giving 84 with the remainder discarded. Make one side a double:

System.out.println("Average: " + (a + b + c) / 3.0);   // 84.66666666666667

To show two decimal places, use System.out.printf("Average: %.2f%n", (a + b + c) / 3.0);, which prints Average: 84.67.

2. Predict the output

Write down what each line prints before running it.

System.out.println(10 / 4 * 4);
System.out.println(1.0 / 3);
System.out.println(Math.round(2.5) + " " + Math.round(-2.5));
System.out.println((char) 66);
Show answer

8 — 10 / 4 is 2, then times 4.

0.3333333333333333 — one side is a double, so the division is real.

3 -2 — Math.round rounds half up, towards positive infinity, so −2.5 becomes −2 and not −3.

B — the cast turns the number back into a character.

3. Read a name and compare it

Use a Scanner to read a word from the keyboard and print whether it is "java", ignoring capitals. Try it first with == and see what happens.

Show answer 
import java.util.Scanner;

public class Compare {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        System.out.print("Type a word: ");
        String word = in.next();
        System.out.println(word == "java");                // always false
        System.out.println(word.equalsIgnoreCase("java")); // what you meant
    }
}

The typed word is a new String object built at run time, so it is never the same object as the literal in your code. This is exactly why == is the wrong tool for objects.
