Java after Python · Chapter 1

Your first Java program

By the end of this chapter you will have compiled and run a Java program, and you will know what every word in it is doing.

Install a JDK

Python comes as one program. Java comes as a kit: a compiler that turns your source code into bytecode, and a virtual machine that runs the bytecode. Together they are the JDK, the Java Development Kit.

Install a current long-term-support release, Java 21 or newer. Adoptium Temurin is a free, open-source build for Windows, macOS and Linux. On Linux you can also use your package manager, for example sudo apt install default-jdk.

Check both tools are there:

javac --version
java --version

Both should print a version number. If java works and javac does not, you installed a runtime rather than a development kit. Install the JDK.

Hello, from Java

Create a file called Hello.java. The name matters: a public class must live in a file with exactly the same name.

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}

Compile it, then run it:

javac Hello.java
java Hello

You get:

Hello, world!

Notice what happened in between. javac produced a new file, Hello.class, holding bytecode. java Hello starts the virtual machine and asks it to run the class called Hello — the class name, not the file name, which is why there is no .class on that line.

Since Java 11 you can skip the compile step for a single file while you are experimenting:

java Hello.java

That compiles in memory and runs it. Handy for a quick test, but your courses will expect you to know the two-step version.

Reading the six words

Python needed one line for this. Java needed five. Here is what each part is for.

  • public class Hello: all Java code lives inside a class. A class is a named box for code and data. public means other code is allowed to use it.
  • static: this method belongs to the class itself, not to an object made from the class. The virtual machine has to call main before any object exists, so main must be static.
  • void: the method returns nothing. Java wants the return type of every method stated up front.
  • main: the name the virtual machine looks for when you run a class.
  • String[] args: an array of strings, holding anything typed after the class name on the command line. Python calls the same thing sys.argv.
  • System.out.println(...): System is a built-in class, out is its standard output stream, and println prints with a newline. print prints without one.

Nothing here is decoration. Java is statically typed: the compiler wants to know the type of every variable, parameter and return value before the program runs, so it can refuse to compile code that would fail. That is the trade. You write more; the compiler catches more.

Semicolons, braces and indentation

Python uses indentation to show what belongs to what. Java uses braces, { and }, and ends each statement with a semicolon. Indentation in Java is purely for humans: the compiler ignores it, but a marker will not.

public class Greet {
    public static void main(String[] args) {
        String name = "Keerit";          // declare the type, then the name
        int year = 1;
        System.out.println("Hi " + name + ", year " + year);
    }
}

That prints:

Hi Keerit, year 1

The + joins strings. When one side is a string, Java converts the other side to a string too, which is why year prints fine without any conversion.

Reading the compiler's complaints

Delete the semicolon after the println line and compile again:

Hello.java:3: error: ';' expected
        System.out.println("Hello, world!")
                                           ^
1 error

Java errors name the file, the line, the problem and point at the column. Read them from the top: the first error often causes the ones below it, so fix one and recompile rather than trying to fix all of them at once.

A different mistake, misspelling a variable, gives:

Greet.java:5: error: cannot find symbol
        System.out.println("Hi " + nme);
                                   ^
  symbol:   variable nme
  location: class Greet

This is the compiler earning its keep. In Python the same typo would wait until that line ran, possibly in front of a marker.

Exercises

1. Three lines

Write and run a class called About that prints your name, your programme and the year on three separate lines.

Show answer 
public class About {
    public static void main(String[] args) {
        System.out.println("Ada Lovelace");
        System.out.println("Computer Science");
        System.out.println(2026);
    }
}

Save it as About.java, then javac About.java and java About. The file name must match the public class name exactly, capital letter included.

2. Use the arguments

Change your program to greet whoever is named on the command line, so that java About Keerit prints Hello, Keerit.

Show answer 
public class About {
    public static void main(String[] args) {
        System.out.println("Hello, " + args[0]);
    }
}

Running it with no argument throws ArrayIndexOutOfBoundsException, because args is empty and there is no args[0]. Guarding against that is what if (args.length > 0) is for, and it is the subject of chapter 3.

3. Break it on purpose

Rename the file to hello.java, with a lower-case h, while the class inside stays Hello. Compile it. Then rename the class instead and compile again. What does each error tell you?

Show answer

With a public class Hello in hello.java the compiler says class Hello is public, should be declared in a file named Hello.java. That rule exists so that the compiler can find a class by its name without reading every file in your project.

If instead you rename the class to hello, it compiles, and java hello runs. It works, but every Java codebase you will ever read capitalises class names, so do the same.
