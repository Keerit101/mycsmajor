Git, Linux and the terminal · Chapter 1

The twelve commands you need

You will spend four years in a terminal. An hour spent on these twelve commands pays for itself in the first week.

Getting a terminal

  • macOS: Terminal, already installed. Everything here works.
  • Linux: likewise.
  • Windows: install the Windows Subsystem for Linux (wsl --install in PowerShell as administrator, then restart). You get a real Ubuntu shell alongside Windows, and your course materials will assume one.

Three keys to know before anything else: Tab completes a name you have half typed, the up arrow recalls the previous command, and Ctrl+C stops whatever is running. Use Tab constantly; it is faster and it prevents typos in file names.

Where am I, and what is here

pwd                  # print working directory: where you are
ls                   # list the files here
ls -l                # long: permissions, owner, size, date
ls -la               # also hidden files, the ones starting with a dot
cd projects          # change directory, into projects
cd ..                # up one level
cd ~                 # your home folder
cd -                 # back to the previous folder

The shell always has a "current folder", and almost every command works relative to it. Two paths you will type constantly: . means here, .. means the folder above.

Relative paths start from where you are (src/main.py); absolute paths start from the root (/home/keerit/src/main.py). When a tutorial command fails, being in the wrong folder is the most likely reason, so check with pwd first.

Making and moving things

mkdir notes              # make a folder
mkdir -p a/b/c           # make the whole chain, no error if it exists
touch main.py            # create an empty file, or update its timestamp
cp main.py backup.py     # copy
cp -r src/ src-copy/     # copy a folder and everything in it
mv old.py new.py         # rename
mv main.py src/          # move into a folder
rm notes.txt             # delete a file
rm -r old-project/       # delete a folder and its contents

There is no recycle bin. rm deletes immediately and permanently. Before any rm -r, run the same path through ls first and read what comes back. Never type rm -rf / or rm -rf ~, and be suspicious of any instruction on the internet that tells you to.

Reading files

cat notes.txt            # print the whole file
less big.log             # page through it: arrows to scroll, / to search, q to quit
head -20 data.csv        # first 20 lines
tail -20 data.csv        # last 20 lines
tail -f server.log       # keep printing as the file grows: Ctrl+C to stop
wc -l data.csv           # count lines

tail -f is how you watch a server's log while you reproduce a bug, and it is worth remembering on its own.

Finding things

Two commands, and knowing which is which saves a lot of time: find searches for files by name, grep searches inside files.

find . -name "*.py"                  # every Python file from here down
find . -name "*.pyc" -delete         # and delete them
find . -type d -name "node_modules"  # folders with that name

grep "TODO" main.py                  # lines containing TODO
grep -r "TODO" .                     # search every file from here down
grep -rn "parse_args" src/           # with line numbers: file:line:text
grep -ri "password" .                # ignore case
grep -rn --include="*.py" "def " .   # only Python files

grep -rn is the single most useful command in this chapter. Dropped into an unfamiliar codebase, it is how you find where something is defined, and it is faster than any search box.

Joining commands with pipes

Each command writes to standard output; a pipe, |, feeds that into the next one. Small tools joined up answer surprisingly specific questions.

grep -r "TODO" . | wc -l            # how many TODOs in the project
ls -l | head -5                     # the first five entries
history | grep git                  # git commands you ran earlier
cat access.log | cut -d' ' -f1 | sort | uniq -c | sort -rn | head
#    ^ read       ^ first field  ^ group identical  ^ count  ^ biggest first

That last line gives the ten busiest IP addresses in a web server log. Note that uniq only collapses adjacent duplicates, which is why sort always comes first; forgetting it is the classic pipeline bug.

Redirection writes to a file instead of the screen: > overwrites, >> appends.

python main.py > output.txt         # replace output.txt
python main.py >> log.txt           # add to the end
python main.py > out.txt 2>&1       # errors go to the same file

Running and stopping programs

python3 main.py          # run it
./script.sh              # run an executable in this folder
chmod +x script.sh       # make it executable first
python3 main.py &        # run in the background
jobs                     # what is running in the background
fg                       # bring it back
Ctrl+C                   # stop the thing in the foreground
Ctrl+Z then bg           # pause it, then continue it in the background

./ is not decoration. The shell looks for programs in the folders listed in PATH, and the current folder is deliberately not one of them — otherwise a downloaded file called ls could replace the real one. ./script.sh says "this exact file, here".

Reading the manual

man grep                 # the full manual: q to quit, / to search
grep --help              # the short version
which python3            # which program actually runs
type cd                  # and what kind of thing it is

Manual pages are dense, but the EXAMPLES section near the bottom usually answers the question you actually had. Press /, type EXAMPLES and press Enter.

Exercises

1. One line each

Write a single command for: (a) count the Python files in a project; (b) find every file mentioning import requests, with line numbers; (c) show the 20 largest files in the current folder, biggest first.

Show answer 
# (a)
find . -name "*.py" | wc -l

# (b)
grep -rn "import requests" .

# (c)
ls -lhS | head -21          # -h human-readable sizes, -S sort by size

In (c) the 21 is not a typo: ls -l prints a total line first. For a recursive version, du -ah . | sort -rh | head -20 works across subfolders too.

2. Clean up a project

Write commands to delete every __pycache__ folder and every .pyc file under the current directory, after checking what will go.

Show answer 
find . -type d -name "__pycache__"      # look first
find . -type f -name "*.pyc"           # and at these

find . -type d -name "__pycache__" -exec rm -r {} +
find . -name "*.pyc" -delete

Always run the find without the deleting part first and read the list. -exec rm -r {} + passes the matches to rm in batches; {} stands for each match and the + ends the command. Better still, add both patterns to .gitignore so they never reach a commit.

3. Build a pipeline

Given a file of one word per line, print the ten most common words with their counts.

Show answer 
sort words.txt | uniq -c | sort -rn | head -10

Sort so identical words sit together, uniq -c collapses each run into a count, sort -rn orders by that count numerically and in reverse, and head takes the top ten.

If the file is real prose rather than one word per line, split it first: tr -s '[:space:][:punct:]' '\n' < essay.txt | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn | head -10. Four small programs, one real answer, no script written.
