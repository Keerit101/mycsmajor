Cyber Brief

Security news, explained for CS students

Each brief covers a real incident: what happened, how it worked, and the lesson you can apply to your own code. Every brief links to its official vulnerability record.

July 2024 · OpenSSH · CVE-2024-6387

regreSSHion: an old bug comes back

Researchers at Qualys found a race condition in the OpenSSH server on glibc-based Linux. If a client failed to log in before the timeout, a signal handler ran code that was not safe to run inside a signal handler. With enough attempts, an attacker could get remote code execution as root without logging in.

The bug was a regression: a fix for a similar 2006 issue (CVE-2006-5051) had been accidentally undone by a later code change.

Lesson: when you fix a bug, add a test that fails if the bug ever returns. Regression tests exist for exactly this.

March 2024 · xz Utils · CVE-2024-3094

The xz backdoor: a two-year supply chain attack

A contributor using the name "Jia Tan" spent about two years earning trust as a maintainer of xz, a compression library used by many Linux systems. Versions 5.6.0 and 5.6.1 shipped with a hidden backdoor in the release tarballs, aimed at the SSH server on some distributions.

It was caught before reaching most stable releases because an engineer, Andres Freund, noticed SSH logins taking about half a second longer than usual and dug into why.

Lesson: your project trusts every dependency and every maintainer behind it. And when something is oddly slow, curiosity is a security skill.

May 2023 · MOVEit Transfer · CVE-2023-34362

MOVEit: SQL injection at scale

MOVEit Transfer is file-transfer software used by many companies and governments. The Cl0p ransomware group exploited a SQL injection flaw in its web application to steal files from a large number of organisations before a patch was available.

SQL injection has been understood for over twenty years, yet it still turns up in commercial products.

Lesson: never build SQL by gluing strings together. Use parameterised queries, for example cur.execute("SELECT * FROM users WHERE id = ?", (user_id,)).

December 2021 · Apache Log4j · CVE-2021-44228

Log4Shell: when logging runs code

Log4j 2, a very widely used Java logging library, supported "lookups": special text like ${jndi:ldap://...} inside a log message would be interpreted, not just written down. If an attacker could get that text logged (in a username, a chat message or an HTTP header), the server could fetch and run the attacker's code.

Because Log4j was buried deep in so many dependency trees, many teams first had to work out whether they used it at all.

Lesson: treat all user input as data, never as instructions. And know what is in your dependency tree; tools that generate a software bill of materials (SBOM) help.

2017 · Apache Struts · CVE-2017-5638

Equifax: the patch that was not applied

A remote code execution flaw in the Apache Struts web framework was disclosed and patched in March 2017. Equifax had not updated a public-facing system, and attackers used the flaw to access personal data of roughly 147 million people.

Lesson: a fix only protects you once it is deployed. Keeping dependencies updated is unglamorous, important work; tools like Dependabot make it easier.

May 2017 · Windows SMBv1 · CVE-2017-0144

WannaCry: a worm with a kill switch

WannaCry ransomware spread on its own between Windows machines using the EternalBlue exploit for the old SMBv1 file-sharing protocol. Microsoft had released a patch (MS17-010) two months earlier, but many systems, including parts of the UK's National Health Service, were not updated.

Its spread slowed when a researcher registered a domain name the malware checked before running, which acted as an accidental kill switch.

Lesson: turn off old protocols you do not need, and read malware the way you would read any program. Its logic can contain its own off switch.

September 2014 · GNU Bash · CVE-2014-6271

Shellshock: code hidden in environment variables

Bash could import function definitions from environment variables, but it kept executing any commands placed after the function body. Web servers running CGI scripts copied HTTP headers into environment variables, so a crafted header could run commands on the server.

Lesson: parsers are an attack surface. Anything that reads untrusted text needs to stop exactly where the valid input ends.

April 2014 · OpenSSL · CVE-2014-0160

Heartbleed: trusting a length field

OpenSSL's TLS "heartbeat" feature let one side send a message and its length, and the other side echoed it back. OpenSSL trusted the stated length without checking it against the real message, so a request claiming to be large returned up to 64 KB of whatever sat next to it in the server's memory, including private keys and passwords.

Lesson: never trust a length, index or size that came from outside your program. Check bounds, or use memory-safe languages and APIs that check them for you.

Security habits worth building now

  • Use a password manager and turn on two-factor authentication for your email and GitHub.
  • Never commit API keys or passwords. Add .env to .gitignore and turn on secret scanning.
  • Use parameterised queries for every database call.
  • Keep dependencies updated, and read what a package does before installing it.
  • Validate input at the boundary: length, type, range and format.
